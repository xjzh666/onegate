# Brief 模板

写 brief 时逐节填充，删掉所有尖括号提示。存为 `.agent/task-N-brief.md`。

```markdown
## 任务 N：<一句话交付物>

### 行为需求
<要什么行为，不是怎么实现。一到三句。>

### 验收标准（可判定）
- <给 X 输入 → 期望 Y 输出>
- <边界：空值 / 重复 / 超长 / 并发时 → 期望 Z>

### Oracle 示例
- 输入 `<具体值>` → 输出 `<具体结构>`
- 输入 `<边界值>` → 输出 `<具体结果>`

### 接口事实
- 消费（已存在，签名从仓库现状抄）：
  - `<函数/类型/端点的真实签名>`
- 产出（本任务完成后可被依赖的）：
  - `<名字 + 签名 + 一句话语义>`

### 范围围栏
- 许动：<文件列表，精确路径>
- 禁动：<文件列表，精确路径>
- 全局约束（逐字复制 spec）：
  - <约束 1>
  - <约束 2>

### 验证契约
TDD：先写失败测试并看它以预期方式失败，再写最小实现让它通过。
报告必须附 RED（命令 + 失败输出 + 为何预期）与 GREEN（命令 + 通过输出）。

### 报告契约
完整报告写 `.agent/task-N-report.md`。
对话里只回：状态 / 提交 SHA / 一行测试摘要 / 顾虑。

开工前有任何不清楚的：先提问（报 NEEDS_CONTEXT），不要猜。
```

**写完 brief 后自查三问**：
1. 验收标准里每一条都能判定 true/false 吗？不能 → 改到能
2. 接口事实是从仓库**现状**抄的，还是从想象写的？想象 → 去读代码
3. 有没有哪个精确值（魔法串、阈值、错误文案、格式）只存在于 spec 里而没进 brief？有 → 逐字搬进来
