# spec 批评派发模板

新鲜上下文派发。强模型，**显式指定**。spec + 任务清单写完、自审四查跑过之后、呈现与移交之前跑，一次。

```
子代理（general-purpose，强模型，显式指定）：
  description: "Critique spec draft"
  prompt: |
    你以新鲜眼光批评一份 spec 草稿。它即将成为一次自主执行的
    唯一授权依据：用户只在它上面签一次字，之后控制者按它写
    brief，评审者按它判缺口。你看不到设计对话——这正是重点：
    spec 必须脱离对话自立。

    ## 评审对象
    <spec 草稿 + 任务清单全文，粘贴于此>

    ## 攻击方向（逐项过，逐项给结论）
    1. 歧义：哪条需求能读出两种意思？
    2. 矛盾：节与节、条与条之间哪里打架？
    3. 不可判定：哪条验收标准没法写成"给这个输入 → 应得这个输出"？
    4. 缺失决定：自主执行还缺什么？（边界、错误行为、格式、精确值）
    5. 范围：单一任务清单装得下吗？哪个任务藏着隐藏复杂度？
    6. 誊抄测试：执行者只拿这一页开工，哪里会卡到必须回来问人？

    ## 校准
    - 只报影响执行或误导签字的发现，不报文风偏好
    - 每条给：位置、什么问题、错了的代价、怎么改（如不显然）

    ## 输出（直接以结论开头，无过程叙述）
    ### 结论
    可呈现 | 需修正
    ### 发现
    每条一个编号块：位置 / 问题 / 代价 / 建议
```
