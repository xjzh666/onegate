# 收尾：最终评审 → 问责 → 移交决定

## 1. 最终评审

- **全量测试**：在当前这棵树上新鲜跑完整套件。早先的绿色只证明早先的树
- **整体通读**：派强模型评审者（显式指定）读整分支 diff 包：
  ```bash
  { git log --oneline BASE..HEAD; echo; git diff --stat BASE..HEAD; echo; git diff -U10 BASE..HEAD; } > .agent/final-diff.md
  ```
  BASE = `git merge-base <基础分支> HEAD`。把台账里的**挂起项**和**延期 minor 清单**一并给它，让它分诊：哪些必须合并前修
  派发里写明：控制者刚在此 HEAD 新鲜跑过全量（结果记台账）——评审**只读 diff 包、不重跑全套件**；仅当读 diff 产生具体疑问才跑聚焦的那一个测试（同 executing 评审规则）
- **文档同步**：代码、文档、CLAUDE.md 三者是否同步（对照项目 CLAUDE.md 的文档维护约定）；缺口走下一行的修复轮
- CLAUDE.md 明显膨胀（堆积历史记录、详细技术说明、重复内容）→ 建议用户拆分；只建议，结构由项目自己定
- 有发现 → **一个**修复者带全部发现修一轮 → 一轮限定复审 → 残余走 executing 的裁决三出口
- **没有第二轮修复潮**。残余的承重发现浮给用户（见下面菜单环节）

## 2. 问责清单（必须在最终消息里）

把台账里**所有** `Ruling:` 按做出的顺序汇成"我做过的裁决"：每条 = 裁决 + 理由 + 错了的代价。

**穷尽**——台账里有一条，清单里就有一条。这是你替用户做的决定抵达用户的唯一途径；漏一条 = 秘密决定。

## 3. 收尾菜单（按原文呈现，等选择）

> 实现完成，全部测试通过。怎么处理？
>
> 1. 本地合并回 `<基础分支>`
> 2. 推送并创建 PR
> 3. 保留分支原样（稍后处理）
>
> 选哪个？

合并 / PR 永远是用户的决定，不替用户选。丢弃只发生在用户明确要求时，且要用户输入 `discard` 确认。

## 4. 执行选择

- **合并**：切回主仓库根目录 → `git checkout <基础分支> && git merge <分支>` → 合并结果上重跑测试 → 绿了才删 worktree 和分支。测试挂了 → 停，一切原地保留，汇报
- **PR**：`git push -u origin <分支>` → 用平台工具建 PR → 报 URL。worktree 保留（PR 反馈在那里改）
- **保留**：汇报分支名和 worktree 路径，结束

## 5. 清理与归档

- **更新 spec 后归档**：
  - 头部加完成标记：`> 状态：已完成 <日期>，合并提交 <SHA>`
  - 执行期间与 spec 不一致的实现——台账里每条 Ruling——逐条补进 spec 对应位置：spec 从意图文档变成**意图 + 结果**文档
  - 提交到 `docs/onegate/specs/`（spec 与任务清单同文件）
  - 执行期间不改 spec：它是裁决的依据，中途修改破坏权威；偏差记台账，收尾统一折入归档版
- 删除 `.agent/`——台账和接手文档写给接班 agent，完工后无接班场景；结果已折进归档 spec，git 历史接管记录
- 只清理自己建的 `.worktrees/` 下的 worktree，其他目录不碰
- 清理后回到**咨询模式**

## 反合理化

| 借口 | 事实 |
|---|---|
| "测试早过了" | 在要收编的这棵树上重跑。 |
| "他们显然想合并" | 菜单按原文呈现，等。 |
| "裁决太多，挑重要的列" | 穷尽。漏一条 = 秘密决定。 |
| "PR 挂上了，worktree 删了吧" | PR 反馈在那个 worktree 里改。保留。 |
| "合并结果失败大概是偶发" | 合并结果失败 = 全停，原地保留，去查。 |
| "spec 就不用留了吧" | 它是批准过的意图 + 执行结果记录。更新后归档。 |
